# 간식 팡팡 (`/snack-pop/`) — 고양이 간식 매치3

## 목표

어르신도 편하게 할 수 있는, 상용 게임처럼 손맛 있는 매치3 퍼즐을 후와 게임에 추가한다.
장르(같은 것 3개 맞추기)만 빌리고 이름·그림·규칙 표현은 우리 것(고양이 간식 가게)으로 만든다.
특정 상용 게임의 이름·캐릭터·그림·레벨을 따라 하지 않는다.

## 현재 상태

- 빌드 없는 정적 사이트. Cloudflare Pages 가 `main` 을 그대로 배포한다.
- 게임 = 폴더 하나(`/<이름>/index.html`). 게이트웨이 `index.html` 의 `.games` 에 카드를 추가한다.
- 기존 게임(고양이 나들이)은 한 파일 905줄, 테스트 없음. 글꼴 Jua/Gowun Dodum, 고양이 그림 `cat-outing/cats/*.webp`.

## 범위

- 새 폴더 `snack-pop/` (ES 모듈 여러 파일, 빌드 없음)
- 8×8 판(레벨에 따라 구멍 있는 모양), 간식 6종(색 + **모양이 다름** — 색약 고려)
- 바꾸기: 끌기(스와이프) 또는 두 번 누르기. 안 맞으면 되돌아가는 애니메이션
- 맞추기: 3개 줄. 4개 → 줄무늬(한 줄 지우기), L/T 모양 → 리본 상자(3×3 터짐), 5개 → 고양이(같은 간식 전부 지우기)
- 특수끼리 바꾸기 조합: 줄+줄 = 십자, 줄+상자 = 3줄 십자, 상자+상자 = 5×5, 고양이+간식/특수, 고양이+고양이 = 판 전체
- 연쇄(떨어진 뒤 다시 맞음), 연쇄 칭찬 문구, 점수, 떠오르는 점수 글자
- 방해물: 얼음(그 칸에서 맞추면 깨짐, 1~2겹), 상자(옆에서 맞추면 깨짐, 1~2겹)
- 레벨 목표: 점수 / 간식 모으기 / 얼음 깨기 / 상자 깨기 (조합 가능), 이동 횟수 제한, 시간 제한 없음
- 별 1~3개(점수 기준), 남은 이동은 끝날 때 보너스로 터뜨림
- 레벨 지도 화면(길 따라 레벨 버튼, 별 표시), 진행은 localStorage `snack-pop.v1`
- 가만히 있으면 둘 곳 힌트(5초), 둘 곳이 없으면 자동 섞기
- 효과음(WebAudio 합성, 파일 없음), 소리 끄기
- 일시정지: 다시 하기 / 지도로
- 다크 모드, 폰 세로 화면 우선, 큰 글씨와 큰 버튼
- 게이트웨이에 카드 추가, README 갱신

## 하지 않는 것

- 빌드 도구·npm 의존성·프레임워크 (배포 방식 그대로)
- 서버·계정·랭킹·결제·광고·생명(하트) 제한
- 레벨 편집기, 무한 레벨 생성
- 배경 음악(효과음만)

## 가정과 제약

- 최신 모바일 브라우저(ES 모듈, Canvas 2D, WebAudio, Pointer Events)
- 이미지 파일을 새로 만들지 않는다. 간식은 Canvas 로 직접 그리고(굵은 진갈색 테두리 + 단색 + 부드러운 음영 — 기존 고양이 그림과 같은 화풍), 고양이 특수 블록은 기존 `cat-outing/cats/01-1.webp`(후와)를 쓴다
- 레벨 데이터는 손으로 만든 20판. 모든 판이 풀 수 있는지 자동 검사(시뮬레이션)는 범위 밖이지만, 초기판에 바로 맞는 줄이 없고 둘 곳이 있음은 테스트로 보장

## 설계

```
snack-pop/
  index.html          화면 틀(지도·게임·대화창), 글꼴, 스크립트 진입
  style.css           디자인 토큰, 라이트/다크, 반응형
  js/main.js          화면 전환, 레벨 시작/끝, 입력 → 엔진 → 연출 연결
  js/core/rng.js      시드 난수 (테스트 재현성)
  js/core/board.js    순수 로직: 판 생성, 맞춤 찾기, 특수 생성, 터뜨리기, 떨어뜨리기, 힌트, 섞기
  js/core/levels.js   레벨 20개 데이터 + 별 기준
  js/render/sprites.js  간식·특수·방해물 그림(오프스크린 캔버스에 미리 그림)
  js/render/view.js   Canvas 렌더러: 조각 위치/크기/투명도, 트윈, 파티클, 흔들림, 글자
  js/render/tween.js  이징·트윈
  js/audio.js         효과음 합성
  js/store.js         localStorage 저장(try/catch)
tests/snack-pop/*.test.mjs   node --test 로 순수 로직 검사
```

핵심 구조: **엔진은 그림을 모른다.** `swap(state, a, b)` 는 상태를 바꾸고 "단계" 목록을 돌려준다
(`swap` → `clear{cells, specialsMade, score}` → `fall{moves, spawns}` → … → `shuffle?`).
조각마다 고유 id 가 있어서 렌더러는 id 로 스프라이트를 찾아 단계를 차례로 연출한다.
그래서 로직은 Node 에서 테스트하고, 연출은 브라우저에서만 다룬다.

# v2: 구경 온 고양이의 부탁 (2026-11-17)

## 목표

고양이가 장식이 아니라 플레이에 끼어들게 한다. 판마다 주인공 고양이(후와·슈리·나비) 하나가 구경 와서
가끔 "생선 줘!" 같은 부탁을 하고, 정해진 턴 안에 들어주면 특수 블록을 선물한다. 사용자 제안을 구체화한 것.

## 현재 상태

- 특수 블록 세 가지(줄무늬·리본 상자·후와)는 맞춤으로만 생긴다. 고양이는 후와가 특수·지도 장식으로만 나온다.
- 엔진은 단계(step) 목록을 돌려주고 렌더러가 차례로 연출하는 구조라, 새 단계 종류를 더하면 된다.

## 범위

- 주인공 셋만: 후와(`01`), 슈리(`04`), 나비(`02`). 나머지 고양이는 이번엔 나오지 않는다(그림은 나중에 새로 그림).
- 판마다 구경 고양이 하나: 1판 후와, 2판 슈리, 3판 나비 … 차례로 돈다.
- 부탁: 블록 한 종류 × 개수, 남은 턴. 간식(생선·발바닥 쿠키·별사탕)은 "줘!", 장난감(털실·방울·캣닢)은 "놀자!" 말투.
- 성격(사용자 확인: 그림 인상대로):
  | 고양이 | 성격 | 쉬는 턴 | 개수 | 턴 | 보상 |
  |---|---|---|---|---|---|
  | 슈리 | 장난꾸러기 막내, 자주 조금 | 2 | 3~4 | 3 | 줄무늬 |
  | 나비 | 새침한 신사, 보통 | 3 | 5~7 | 4 | 리본 상자 |
  | 후와 | 도도한 대장, 드물게 크게 | 5 | 8~10 | 5 | 후와(싹쓸이) |
  보상은 요청 크기로 정한다(≤4 줄무늬, ≤7 리본 상자, 8+ 후와) — 성격이 크기를 정하므로 결과적으로 고양이마다 다르다.
- 성공: 고양이가 판에 특수 블록을 던져 넣는다(일반 간식 하나가 특수로 바뀜, 날아가는 연출). 점수 없음.
- 실패: 벌칙 없음. 삐진 말풍선 뒤 쉬었다가 다시 부탁.
- 첫 부탁은 첫 수를 둔 뒤. 남은 이동이 부탁 턴보다 적으면 새 부탁을 하지 않는다. 이긴 뒤(보너스 타임)엔 부탁 없음.
- 연출: 고양이가 판 오른쪽 화면 끝에서 빼꼼 나와 말풍선(블록 그림 ×개수 + 대사) → 2초쯤 뒤 쏙 들어감.
  미션은 점수바 옆 작은 칩(고양이 얼굴 · 블록 그림 · 3/5 · 남은 턴 점). 칩을 누르면 고양이가 다시 빼꼼.
- 판 소개 창에 "오늘의 손님" 표시.

## 하지 않는 것

- 쩌리 고양이 등장, 새 그림, 고양이 설정 화면, 부탁 실패 벌칙, 부탁 점수

## 설계

- `js/core/cats.js`: 고양이 프로필(이름·그림 번호·쉬는 턴·개수 범위·턴·대사).
- `board.js`: 상태에 `guest`, `request`({kind, need, have, turnsLeft}), `requestRest`.
  맞춤으로 지워진 조각(`cleared` + `kept`)이 부탁 종류면 `have` 증가.
  `swap()` 이 끝날 때(연쇄·섞기 뒤) 부탁 처리 → 새 단계:
  `{type:'gift', cat, id, r, c, kind, special}` / `{type:'requestEnd', cat, ok:false}` / `{type:'request', cat, kind, need, turns}`.
  선물은 둘 곳을 없애지 않는다(조각 색은 그대로, 특수만 바뀜; 후와는 색 -1 → 힌트 다시 확인, 없으면 섞기).
- 렌더러: `gift` = 화면 오른쪽에서 선물이 포물선으로 날아와 그 칸이 특수로 바뀜. `request`/`requestEnd` 는 판 연출 없음.
- `main.js`: 고양이 빼꼼·말풍선(DOM, 판 위 오버레이, 입력 막지 않음), 미션 칩.

## 완료 기준

1. 판마다 정해진 고양이가 첫 수 뒤 오른쪽에서 빼꼼 나와 부탁하고 들어간다. 칩에 미션이 남는다
2. 부탁한 블록을 지우면 칩 숫자가 오르고, 다 채우면 고양이가 나와 기뻐하며 특수 블록을 던져 넣는다
3. 턴 안에 못 채우면 삐진 말풍선, 쉬었다가 다시 부탁
4. 390px 에서 판·HUD 가 가려지지 않고 가로 스크롤 없음, 다크 모드 정상
5. 테스트 통과(부탁 생명주기·보상 크기·단계 불변식), 콘솔 오류 없음
6. 난이도 시뮬레이션 다시 돌려 별 기준 조정

# 난이도 다시 맞추기 (2026-11-18)

## 목표

"깨기는 쉬운데 3별은 어렵다"를 고친다.
- 클리어는 조금 빡빡하게: 잘 두면 이동이 3분의 1쯤 남는다.
- 별은 클리어하면 1개, 보통으로 두면 2개, 잘 두면 3개.

## 현재 상태 (시뮬레이션, 판마다 12번)

- 목표만 노리는 봇(모든 수를 한 수 앞까지 봄)은 1~15판을 다 깨고, 이동이 절반 넘게 남는다(1판 20수 중 18수, 11판 25수 중 20수).
- 점수 대부분이 보너스 타임(남은 이동 × 300 + 줄무늬 연쇄)에서 나와 운 영향이 크다.
- 별 기준이 그 봇 중앙값의 1.05배라 잘 두는 봇도 3별은 25~58%다.

## 범위

- `levels.js`의 이동 수와 별 기준만 바꾼다. 규칙, 점수 계산, 목표 종류는 그대로 둔다.
- 하지 않는 것
  - 목표량 변경
  - 보너스 점수 공식 변경
  - 16·18·19·20판(지금도 봇 승률 90% 미만)의 이동 줄이기

## 방법

1. 판마다 이동을 줄여, 잘 두는 봇이 남기는 이동의 중앙값이 전체의 약 3분의 1이 되게 한다. 단, 봇 승률은 90% 이상을 지킨다.
2. 바뀐 이동으로 판마다 24번 다시 돌려 별 기준을 정한다.
   - 2별: 잘 두는 봇 점수의 하위 15%
   - 3별: 같은 점수의 하위 40%. 그러면 잘 두는 봇이 3별을 60%쯤 받는다.
   - 1별: 이기면 언제나 받는다(기존 규칙).

## 완료 기준

- 1~15판(16판 제외)에서 잘 두는 봇의 남는 이동이 약 25~40%다.
- 모든 판에서 잘 두는 봇의 3별 비율이 50~70%다.
- 테스트가 모두 통과하고, 브라우저에서 한 판을 끝까지 둬서 별 창을 확인한다.

## 난이도 구현 결과

- 처음 방법(잘 두는 봇 기준으로 이동 줄이기)은 1판이 20→10수가 될 만큼 사람에게 지나쳐서 버렸다.
- 바꾼 기준
  - 이동 수: 보통 봇(아무 수 셋 중 나은 수)이 85% 넘게 깨는 선까지만 줄이고, 원래의 70% 밑으로는 내리지 않았다.
  - 별: 2별은 보통 봇 중앙값이고 3별은 잘 두는 봇 하위 35%다. 단, 2별은 3별의 80% 이하로 둔다.
- 이동 변경: 1판 20→14, 2판 20→18, 3판 22→18, 5판 20→14, 6판 24→22, 11판 25→19. 나머지 판은 보통 봇에게 이미 쉽지 않아 그대로 둔다.
- 결과(판마다 24번)
  - 잘 두는 봇은 3별을 54~75% 받는다. 다만 16·20판은 승률이 42~46%라 3별이 25~33%다.
  - 보통 봇은 앞쪽 판에서 2별 58~75%, 3별 25~42%다.
- 확인
  - 테스트 69개가 통과한다.
  - Orca 브라우저에서 1판(14수)을 힌트 수만 둬서 끝까지 했다. 4수 남기고 클리어해 6,180점, 별 1개 창이 떴다.

# 갇히는 얼음 (2026-11-18)

## 목표

사용자가 "얼음 안 블록도 움직여져서 얼음이 의미가 없다"고 했다. 지금 얼음은 블록 아래 바닥 판이라 블록이 자유롭게 움직인다. 얼음 칸의 블록이 얼음에 **갇히도록** 바꾼다(사용자 선택).

## 규칙

- 얼음(1·2겹) 칸의 간식은 바꿀 수 없고, 떨어지지도 않는다(제자리 고정).
  - 위 간식은 상자처럼 그 칸을 지나 아래로 떨어진다.
  - 섞기에서도 움직이지 않는다.
- 갇힌 간식도 같은 색 줄에는 낀다. 이럴 때 얼음이 한 겹 깨진다(한 단계에 한 겹만):
  - 줄에 끼었을 때
  - **바로 옆에서 맞췄을 때**(상자와 같음)
  - 특수 블록이나 후와 싹쓸이에 맞았을 때
  - 깨지는 동안 간식은 사라지지 않는다. 모으기나 부탁 개수에는 세지 않고, 얼음 점수만 준다.
  - 마지막 겹이 깨지면 간식이 풀려 보통 간식이 된다. 그대로 줄이 맞아 있으면 다음 연쇄에서 터진다.
- 갇힌 칸에는 특수 블록이 생기지 않는다. 선물, 보너스 타임 변환, 후와+특수 조합 변환 대상에서도 뺀다.
- 그림: 얼음을 간식 **위**에 반투명으로 덮어 그린다(갇힌 느낌).
- 4판 안내 문구를 "얼음에 갇힌 간식은 못 움직여요. 옆에서 맞춰 깨요"로 바꾼다.

## 영향

- `board.js`: `canSwap`, `applyGravity`, `runClear`, `creationCell`, `giveGift`, `bonus`, `shuffle`, 후와+특수 변환
- `view.js`: 얼음 그리는 순서
- `sprites.js`: 얼음 그림
- `levels.js`: 4판 문구, 얼음 판 이동 수·별 재조정(4·7·10·13·16·17·18·19·20판)
- 테스트: 얼음 관련 기존 테스트를 새 규칙으로 고친다. 갇힘 테스트를 추가한다(바꾸기 불가, 떨어지지 않음, 깨지는 동안 남음, 풀린 뒤 이동 가능, 섞기에서 고정).

## 완료 기준

- 테스트가 통과한다.
- 리뷰 재생기(렌더러 모형) 불변식이 얼음 판에서도 깨지지 않는다.
- 얼음 판도 잘 두는 봇의 승률과 3별 비율이 이전 기준(승률 90%↑, 3별 50~70%)을 지킨다. 후반 어려운 판은 예외로 둔다.
- 브라우저: 4판에서 갇힌 간식을 끌어도 안 움직이고, 옆에서 맞추면 얼음이 깨진 뒤 움직일 수 있다.

## 갇히는 얼음 구현 결과

  - 잘 두는 봇 승률이 10·13판 46%, 16판 0%, 20판 13%였다.
