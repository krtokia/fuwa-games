# 후와 게임 — game.fuwa.dad

빌드 없는 정적 사이트. Cloudflare Pages 가 main 을 그대로 배포한다.

- `/` — 게이트웨이(게임 목록). 게임을 추가하면 `index.html` 의 `.games` 에 카드를 하나 더 넣는다.
- `/cat-outing/` — 고양이 나들이. 판 = 칸 수(3~7) × 난이도(쉬움~아주 어려움, `DIFFS` 표) × 판 번호(1~99999), 셋이 같으면 같은 판. 기록·별·고양이 빈도는 localStorage `cat-outing.v2`. 고양이 이름은 실제 이름이라 고정(그림 번호: 01 후와 · 04 슈리 · 02 나비 · 03 두부 · 07 봉봉 · 08 로로 · 05 꼬미 · 06 나무 순서. 기본 등장은 후와·슈리·나비 2배), 사람별로는 등장 빈도만 바꾼다. 고양이 그림은 `cat-outing/cats/<번호>-<칸수>.webp`(320px, 위를 보는 모습, L칸이면 세로 L배). 원본 512px PNG 는 GPT 가 up.fuwa.dad 로 올린 것.

새 게임은 폴더 하나(`/<이름>/index.html`)로 넣는다. 경로는 폴더 안 상대 경로로 쓸 것.

## 후와 달리기 v0.11 · 입체 골목과 생선 경로

`/cat-runner/`는 Phaser 3.90 기반 시간제 러너다. 기본 속도는 360px/s, 선택 속도는 240px/s다. 일반 플레이어의 조작감을 먼저 다듬는다. 정적 파일만으로 Cloudflare Pages에서 실행하며 서버·컨테이너는 필요 없다.

### 시간과 기록

- **30초로 시작**, 포션을 먹으면 **10초 추가**, 장애물 충돌·추락·턱 충돌은 **5초 감소**다. 별도 기운이나 목숨은 없다. 남은 시간이 0이면 종료하며, 44초 도착점은 제거했다.
- `STARTING_SECONDS`, `POTION_SECONDS`, `COLLISION_PENALTY_SECONDS`로 기본값을 관리한다. 시험용 `createGame(mode,width,{seed,collisionPenaltySeconds})`로 피격 감소량을 바꿀 수 있다.
- 하악 반응 0.85초에는 남은 시간, 세계 시간, 장애물, 포션, 점프 물리와 무적 시간도 멈춘다. 반응 중 입력을 저장하지 않는다. 마지막 충돌로 시간이 0이 되면 표정을 보여 준 뒤 결과가 나온다. 일시정지는 남은 반응도 보존한다.
- 시간 만료는 같은 틱의 포션보다 먼저 처리한다. 충돌 틱도 즉시 멈추므로 뒤늦은 포션이 종료를 되돌리지 않는다. 추락 복구는 한 번의 벌점 뒤 안전한 바닥으로 이어진다.
- 포션은 점수·간식 수에 포함하지 않는다. 생선 10점, 별 50점, 연속 통과 20–40점이다. 최고 점수는 `fuwa-runner.v2`의 `score_v11_<mode>`로 이전 버전과 구분한다. 서로 다른 길은 생존 시간과 획득 가능한 점수가 달라질 수 있다.

### 검증한 패턴의 무작위 조합

- `course.mjs`에 6초 길이의 패턴을 정의한다. 첫 구간은 낮은 상자 하나로 시작하고, 이후에는 13가지 패턴을 조합한다. 기존 상자·화분·높은 상자·구멍 패턴에, 툇마루 위 상자, 낮은 정원의 긴 화분, 두 단계 계단, 높은 길 사이의 구멍, 낮은 골목으로 내려가는 구멍을 추가했다.
- 구간은 모두 높이 0의 안전한 바닥에서 시작하고 끝난다. 중간 지형은 기존 −54·+48 외에도 +28·+56의 계단, +36·+40의 툇마루, −32·−36의 낮은 길과 실제 구멍을 포함한다. 패턴 끝에는 착지·포션 수집 공간이 있고, 다음 구간의 첫 장애물은 패턴에 따라 1.15–1.55초에 등장한다. 장애물 하나씩 무작위로 뿌리지 않는다.
- 각 패턴은 난이도 1–4다. 같은 패턴의 연속 선택 가중치는 0.6배로 줄인다. 시간대별 각 패턴의 난이도 가중치는 24초 전 `[7,5,1,0]`, 24–60초 `[3,5,3,1]`, 이후 `[2,4,5,3]`이다. 속도를 계속 올리는 대신 더 복잡한 조합의 비중을 늘린다. 이는 **패턴별** 가중치이며 난이도별 전체 비율과 같지는 않다.
- Mulberry32의 32비트 시드를 사용한다. 화면 폭·프레임 속도·수집 결과는 선택 난수에 영향을 주지 않는다. 같은 게임 버전에서 화면의 8자리 16진수 길 번호가 같으면 같은 순서다. 패턴을 추가한 새 버전은 같은 번호라도 이전 버전과 다른 길이 될 수 있다. 결과의 **같은 길 다시**는 시드를 유지하고 **새로운 길 달리기**는 새 번호를 뽑는다. 링크에 `?seed=00000001`처럼 넣어 재현할 수 있다.
- 포션은 선택된 구간의 안전한 출구(구간 시작 후 5.35–5.65초)에 들어간다. 첫 포션 중심은 11.35–17.65초, 다음 중심 간격은 11.70–18.30초로 제한한다. 실제 수집은 후와의 넉넉한 획득 범위 때문에 조금 더 빠르다. 포션이 전혀 안 나오는 무제한 가뭄은 없다.
- 포션 공급 속도는 소비보다 느리다. 최선의 배치와 무피격 플레이도 최대 10개, **130초 이내**에 끝난다. 영구 생존을 보장하지 않는다. 점프를 계속하거나 포션을 지나치면 놓칠 수 있다.
- 필요한 앞쪽 구간만 생성하고 뒤쪽 구간·장애물·보상은 제거한다. 더 오래 달린다고 모든 과거 지형을 쌓아 두지 않는다.

### 생선과 별의 경로

- 장애물 위에 임의의 높이로 보상 3개를 놓던 방식을 바꿨다. 실제 점프 속도·중력·지형을 사용하는 궤적을 계산하고, 후와의 몸 중심을 따라 생선과 별을 배치한다. 기준 플레이는 첫 안내와 두 번째 안내에 각각 150ms 뒤 반응한다.
- 올라가는 턱, 높은 길 위 상자, 내려가는 바닥, 낮아진 구멍의 착지 높이를 함께 반영한다. 공중의 노드 하나씩만 따로 닿는지를 보는 대신, 한 번의 연속 플레이로 경로의 보상을 모을 수 있는지 검사한다.
- 낮은 상자 두 개가 있는 패턴에는 선택 보상인 민트색 고리 별길을 둔다. 낮은 기본 점프로 안전하게 지나가도 되며, 첫 입력 후 0.35초에 뜨는 선택 안내에 맞춰 공중에서 한 번 더 누르면 위쪽 별길을 따라갈 수 있다. 필요한 장애물 안내가 선택 안내보다 우선한다.
- 필수 2단 점프 경로의 별은 노란색, 선택 별길은 민트색 고리로 구분한다. 포션은 계속 안전한 출구에 두며 선택 별길을 타야만 얻도록 바꾸지 않는다. 보상 수집은 정확한 타이밍에 따른 선택이며, 모든 허용 반응 지연에서 전부 수집된다고 보장하지 않는다.
- 생선과 별은 조금 작게 표시해 느린 속도에서도 경로가 뭉쳐 보이지 않도록 했다. 포션 크기와 터치 버튼 크기는 유지한다.

### 조작과 표현

- 한 번 누르면 낮은 점프, 떼었다가 공중에서 다시 누르면 2단 점프다. 누르는 길이는 높이를 바꾸지 않는다. 입력 순간 반응하며 세 번째 입력과 자동 반복은 받지 않는다.
- 첫 점프 체공 시간은 약 0.663초다. 2단 점프에 모으기·차기 그림 두 장, 착지에 눌림·회복 그림 두 장을 쓴다. 각 동작은 약 0.14초이며 새 입력은 착지 동작을 즉시 끊고 점프한다.
- 최소 월드 가로 폭은 720이다. 좁은 화면에서도 HUD와 터치 버튼 크기는 유지한다. 보이는 코끝 235px 기준 기본 속도에서 약 1.35초의 접근 구간을 확보한다. 높은 점프가 안내 문구를 가리지 않도록 안내는 버튼 옆에 둔다.
- 낮은 상자 폭은 속도×0.12초, 긴 화분은 ×0.64초, 구멍은 ×0.70초다. 높은 상자는 높이 105px, 폭 속도×0.16초다. 긴 화분과 높은 상자는 단일 점프로 넘을 수 없다. 구멍은 걸어 나간 뒤 남은 공중 점프로 복구하는 여유를 허용한다.
- 첫 안내는 보통 0.50초 전, 높은 상자는 0.81초 전에 시작한다. 두 번째 안내는 첫 입력 후 긴 화분·구멍 0.18초, 높은 상자 0.14초다. 먼 거리 경고는 “준비”, 입력 시점은 “지금 톡”으로 구분한다.
- 시간 포션은 민트색 `+10` 병으로 표시하며 획득 시 `+10초` 글자와 별도의 3음 효과를 낸다. 병은 코드로 그린 소품이고 후와 그림은 기존 생성 에셋을 유지한다.
- 소리는 기본 꺼짐이다. 켜면 112BPM 합성 음악과 짧은 효과음이 나온다. 하악은 약 0.32초의 합성 소리이며 실제 고양이 녹음이 아니다.
- 기존 `cat-outing/` 코드·그림·기록은 바꾸지 않는다. 탭 이탈과 화면 크기 변경은 일시정지한다.

### 배치에 쓰는 계산

첫 점프 속도 440, 상승 중력 1250, 하강 중력 1600이다. 상승 구간은 `y(t)=440t−625t²`이며, 정점까지 0.352초, 최고 높이 77.44px다. 정점 뒤에는 하강 중력으로 계산해 같은 바닥까지 총 약 0.66313초가 걸린다. 2단 입력은 현재 속도에 더하지 않고 위쪽 속도 520으로 교체한다. 가능한 최고 높이는 185.60px다.

긴 화분의 실효 충돌 높이 22px 위에 머무는 단일 점프 시간은 약 0.561초다. 화분 폭과 몸통·충돌 여유를 포함한 구간은 기본 속도 약 0.673초, 느린 속도 0.690초여서 한 번의 점프로 부족하다. 높은 상자는 실효 높이 95px가 첫 점프 최고 77.44px보다 높다.

각 패턴의 장애물 앞뒤와 모든 패턴 연결을 실제 안내 시점 기준으로 검사한다. 첫·두 번째 안내에 80–250ms 늦게 반응하는 경우, 30/60/120Hz, 두 속도를 포함한다. 낙차 뒤에는 자동으로 내려앉고, 상승 턱은 점프해야 한다.

### 그림의 출처와 한계

후와 그림은 실제 참고 그림 https://fuwa.dad/assets/ref/fuwa/fuwa-pose-stand-side.png 와 https://fuwa.dad/assets/ref/fuwa/fuwa-front.png 를 보고 이미지 생성 도구로 만들었다.

- `fuwa-generated.png`: 시작·대기 포즈.
- `fuwa-motion-v1.png`: 실제 다리와 몸 자세가 다른 달리기 6프레임, 상승·하강 2포즈.
- `fuwa-jump-land-v1.png`: 2단 점프 모으기·차기, 착지 눌림·회복의 서로 다른 4포즈.
- `fuwa-hiss-front-v1.png`: 플레이어를 보는 정면 하악 포즈 한 장. 몸을 돌리는 연속 회전 애니메이션은 아니다.
- `moonlit-alley-v1.png`: 생성한 한옥 골목 배경. 완벽한 반복 타일이 아니므로 제한된 범위에서 천천히 이동한다.

새 동작은 실제 그림 교체와 작은 자세 보정이며, 완성된 리깅 애니메이션은 아니다. 프레임마다 털·체형·정합에 작은 차이가 있고 일부 다리가 긴 털과 섞인다. 차기 그림의 발이 가상 기준점 아래로 뻗는 부분은 바닥 가까이에서 그림 위치만 보정한다. 충돌 판정은 그림의 외곽선이나 프레임에 따라 바꾸지 않는다. 상세 출처와 프롬프트는 `cat-runner/assets/` 문서에 있다.

### 실행과 검사

`physics.mjs`는 실제 게임과 보상 궤적이 공유하는 점프 계산, `rewards.mjs`는 구간별 수집 경로를 담당한다. 후와의 실제 물리를 보상 위치에 맞추어 바꾸지는 않는다.

Pages의 빌드는 필요 없다. Phaser 런타임을 MIT 라이선스와 함께 저장소에 포함하여 외부 CDN 없이 정적으로 실행한다.

```sh
python3 -m http.server 8000
# http://localhost:8000/cat-runner/
node --test cat-runner/tests/*.test.mjs
node --check cat-runner/game.mjs
```

`python3 cat-runner/scripts/build-standalone.py /tmp/fuwa-runner.html`로 오프라인 검토용 단일 HTML을 만들 수 있다. 운영 배포에는 이 단계가 필요 없다.

자동 검사는 두 속도, 여러 화면 폭·프레임 속도·시드, 패턴 연결, 포션 간격, 시간 만료·충돌·수집의 순서, 지형 경계, 마지막 순간의 점프, 피격 정지, 일시정지, 재시작을 포함한다. 실제 장면 갱신 함수를 쓰는 렌더링 대역 검사와 터치 형태의 Pointer Event 검사도 있다. 이는 실제 휴대폰이나 브라우저 모바일 에뮬레이션을 대신하지 않는다. 기기 터치·화면 회전·소리 청취는 별도 검토가 필요하다.

기능 브랜치를 푸시하면 Cloudflare Pages 미리보기에서 검토한다. main 병합은 별도이며 병합 시 운영 사이트에 새 경로와 목록 카드가 배포된다.
